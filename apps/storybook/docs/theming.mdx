# Theming

Faber UI supports a CSS-first theme contract and an optional React provider. Components consume
semantic CSS variables, so applications can change colors without rewriting component styles or
depending exclusively on React context.

## Load the default themes

Import styles once at the application entry point:

```tsx
import '@faber-ui/react/styles.css';
```

The aggregate stylesheet loads both the packaged font and theme variables. Use
`@faber-ui/react/theme.css` when only theme variables are desired.

The packaged themes pair Amethyst primary colors with Obsidian accents. Light mode uses silver
gray neutrals and white surfaces; dark mode uses graphite and gunmetal neutrals with brighter brand
steps for readable contrast. Brand hues are reserved for actions, focus, and emphasis instead of
page backgrounds.

Both themes are checked against WCAG 2.2 AA in the test suite: text roles reach 4.5:1 on the
background and surface roles, text on primary and accent fills reaches 4.5:1 in the rest, hover,
and pressed states, and `BORDER_STRONG` and `FOCUS_RING` reach 3:1. Text set on a tint of its own color, as in a light `Button`
or a `Badge`, is mixed toward the text color by `OPACITIES.TEXT_ON_TINT` so it also reaches 4.5:1.
`BORDER_DEFAULT` is a
decorative divider and is not meant to mark the edge of a control. A custom theme should keep
the same pairs readable.

## React provider

```tsx
import { GlobalStyles, THEME_MODES, ThemeProvider } from '@faber-ui/react';

export function Application() {
  return (
    <ThemeProvider mode={THEME_MODES.DARK}>
      <GlobalStyles />
      ...
    </ThemeProvider>
  );
}
```

The provider accepts `THEME_MODES.LIGHT`, `THEME_MODES.DARK`, or their equivalent string literals.
It supplies the selected theme to styled-components and writes the same semantic CSS variables on
its boundary. `THEME_MODES.SYSTEM` is reserved for the CSS-only `data-theme` contract.

`GlobalStyles` is optional. When rendered once at the application boundary, it applies Faber UI's
minimal document baseline without resetting semantic styles for headings, paragraphs, lists,
links, or buttons. Customize the baseline through themes, semantic CSS variables, or application
CSS rather than component props.

## CSS-only themes

Theme variables can be activated without React context:

```html
<html data-theme="light">
  <!-- application -->
</html>
```

Supported CSS values are `light`, `dark`, and `system`. System mode follows the operating-system
preference:

```html
<html data-theme="system">
  <!-- follows prefers-color-scheme -->
</html>
```

## Override semantic variables

Customize an application globally:

```css
:root {
  --faber-ui-font-family-base: Inter, Arial, sans-serif;
  --faber-ui-color-primary: hsl(220 80% 48%);
  --faber-ui-color-primary-hover: hsl(220 80% 40%);
  --faber-ui-color-primary-active: hsl(220 80% 32%);
  --faber-ui-color-on-primary: #ffffff;
}
```

Or scope a brand variation to one subtree:

```css
.campaign {
  --faber-ui-color-accent: hsl(25 90% 48%);
  --faber-ui-color-accent-hover: hsl(25 90% 40%);
  --faber-ui-color-accent-active: hsl(25 90% 32%);
}
```

## The modal overlay

`--faber-ui-color-overlay` is the scrim behind `Dialog`, `Drawer`, and `AlertDialog`. Unlike the
other roles it carries its own transparency, and it is dark in both built-in themes: lighter in
the light theme, deeper in the dark one. A complete custom theme must define `OVERLAY`.

```css
:root {
  --faber-ui-color-overlay: hsl(222 47% 8% / 70%);
}
```

## Shadows

`--faber-ui-color-shadow` is the color of every elevation shadow. Like the overlay it carries its
own transparency and is deeper in the dark theme, where a light shadow would not show. A complete
custom theme must define `SHADOW`.

```css
:root {
  --faber-ui-color-shadow: hsl(260 40% 20% / 14%);
}
```

## Focus on text fields

`Input`, `Textarea`, and `Select` mark focus on their own border instead of drawing a ring around
it. The border grows to `FOCUS_RINGS.FIELD_BORDER_WIDTH` and takes `--faber-ui-color-primary`, with
a faint halo of the same color `FOCUS_RINGS.HALO_WIDTH` wide, so a brand override of the primary
role restyles it. Every other control keeps the outer ring in `--faber-ui-color-focus-ring`.

## Retune dimensions

Spacing, sizes, radii, border widths, font sizes, font weights, and line heights are CSS variables
too. Override them globally or within a subtree to change the shape of every component that reads
them:

```css
:root {
  --faber-ui-radius-md: 2px;
  --faber-ui-size-md: 44px;
}

.compact {
  --faber-ui-spacing-md: 12px;
  --faber-ui-font-size-sm: 13px;
}
```

See [Design Tokens](?path=/docs/foundations-design-tokens--docs) for the full list.

## Style one part of a component

Every component and every part inside it has a stable class name: `faber-ui-<component>` on the
root and `faber-ui-<component>-<part>` on each part. They let any stylesheet restyle one part
without wrapping the component.

```css
/* Every button icon in the application. */
.faber-ui-button-icon {
  opacity: 0.7;
}

/* Only inside a toolbar. */
.toolbar .faber-ui-button-label {
  text-transform: uppercase;
}

/* The thumb of every switch. */
.faber-ui-switch .faber-ui-choice-control-input::after {
  border-radius: 2px;
}
```

The names follow the component and part names: `faber-ui-button`, `faber-ui-button-content`,
`faber-ui-button-icon`, `faber-ui-button-label`, `faber-ui-field-label`, `faber-ui-dialog-header`,
`faber-ui-tab`, and so on. Typography members are `faber-ui-text-p`, `faber-ui-title-h1`, and
similar, and icons carry `faber-ui-icon`. `Checkbox`, `Radio`, and `Switch` share their parts
(`faber-ui-choice-control-*`) under a root class of their own. The class names are part of the
public contract.

Prefer a theme variable when the change is a color or a dimension that should apply everywhere,
and a part class when one part needs a rule of its own.

## Custom typed theme

The React provider also accepts a complete typed theme object:

```tsx
import { LIGHT_THEME, ThemeProvider } from '@faber-ui/react';
import type { TTheme } from '@faber-ui/react';

const BrandTheme = {
  ...LIGHT_THEME,
  PRIMARY: 'hsl(220 80% 48%)',
  PRIMARY_HOVER: 'hsl(220 80% 40%)',
  PRIMARY_ACTIVE: 'hsl(220 80% 32%)',
} satisfies TTheme;

export function BrandedArea() {
  return <ThemeProvider theme={BrandTheme}>...</ThemeProvider>;
}
```

A custom theme must satisfy the complete `TTheme` contract. For a small override, CSS variables
are usually the simpler option.

## Theme responsibilities

- Themes define semantic color decisions.
- Tokens provide stable component references and fallbacks.
- Components do not own application-specific brand values.
- Applications can override semantic variables without using a style-prop system.
