# Faber UI

Faber UI is a modular, strongly typed design system for React, Next.js, and Vite. This Storybook
is its living manual: component APIs are generated from source, while these guides explain the
decisions and contracts shared across components.

The project is public and under active development. The packages are published on npm under the
`@faber-ui` scope; until 1.0, a minor version may change an API.

## What is available

- Primitive palette tokens and semantic color tokens.
- Light, dark, and CSS-driven system themes.
- An opt-in `GlobalStyles` document baseline, installed globally in Storybook.
- Plus Jakarta Sans Variable distributed as local package assets.
- Responsive dimensional, typography, border, radius, and motion tokens.
- Accessible `Button` and `IconButton` atoms, and `LinkButton` and `Link` for navigation.
- An independent `@faber-ui/icons` package with a first set of outline icons.
- A native `Input` atom that preserves input attributes, events, and refs.
- A native `Textarea` atom with rows-based height and vertical resizing.
- Native `Checkbox`, `Radio`, and `Switch` atoms with inline labels, form props, and validation
  messages.
- A native `Select` atom that preserves option children, form props, and refs.
- A `Field` molecule that associates labels, descriptions, and validation errors with controls.
- A `RadioGroup` molecule that labels a set of radios with a native `fieldset` and `legend`.
- A `SegmentedControl` molecule built from native radios.
- Responsive `Flex`, `HFlex`, and `VFlex` layout atoms with token-aware gaps and optional debug
  outlines.
- A responsive page `Container` with automatic breakpoint widths and custom maximum sizes.
- A constrained `CenterFlex` composition for centering children on both flex axes.
- Semantic `Text.*` and `Title.*` typography atoms, including inline `Text.Code`.
- `Divider`, `Badge`, `Avatar`, `Card`, `Table`, and `Alert` display atoms.
- `Spinner`, `Skeleton`, and `Progress` loading atoms with reduced-motion handling.
- Native-first `Slider`, `Autocomplete`, `Accordion`, `Breadcrumb`, and `Pagination`.
- `Tabs`, `Toast`, and a modal `Dialog` and `Drawer` built on the native `dialog` element.
- `Tooltip`, `Popover`, and `Menu`, with Radix as an internal implementation detail.
- A `VisuallyHidden` atom for content exposed only to assistive technology.
- Public `CONSTANT_CASE` objects for closed component options and theme modes.
- Autodocs, interaction examples, theme previews, and automated accessibility checks.

## Core principles

- Prefer semantic HTML over unnecessary abstractions.
- Target WCAG 2.2 AA.
- Provide explicit native props, reliable public types, and correctly forwarded refs.
- Use semantic tokens and CSS variables as the customization contract.
- Keep APIs constrained while preserving `className`, `style`, and CSS-variable escape hatches.
- Keep Radix as an internal implementation detail for complex behavior.
- Build small, responsive, predictable components documented with realistic examples.

## Documentation map

- **Getting Started** covers styles, fonts, themes, and the first component imports.
- **Design Tokens** explains the primitive-to-semantic token architecture.
- **Theming** documents CSS, React provider, system mode, and customization.
- **Composition** documents props, part classes, tokens, and building components from parts.
- **Typography** documents semantic `Text.*` and `Title.*` usage.
- **Forms** documents Input, Textarea, Select, Field, Checkbox, Radio, RadioGroup, Switch,
  validation libraries, and translated copy.
- **Components** contains human-readable guides for every implemented React component. Each guide
  explains purpose, behavior, accessibility, customization, examples, and boundaries.
- **Atoms**, **Molecules**, and **Organisms** contain interactive component references generated from their
  stories and types.

## Project status

The foundation is operational and validated through type checking, linting, unit tests, package
builds, and a static Storybook build. Visual details remain intentionally iterative while the
component contracts and accessibility behavior stabilize.
