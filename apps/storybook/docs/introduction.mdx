# Faber UI

Faber UI is a strongly typed design system for React. Components render the native element you
would have written by hand, take their look from design tokens, and expose CSS variables and
stable class names as the way to change them.

The packages are published on npm under the `@faber-ui` scope. Until 1.0, a minor version may
change an API.

## Where to start

- [Getting Started](?path=/docs/introduction-getting-started--docs): install, load the styles,
  and render the first component.
- [Components](?path=/docs/components-overview--docs): one guide per component, with its
  behavior, accessibility notes, and boundaries.
- [Design Tokens](?path=/docs/foundations-design-tokens--docs) and
  [Theming](?path=/docs/foundations-theming--docs): the values behind every component and
  how to replace them.
- [Composition](?path=/docs/foundations-composition--docs): props, part classes, and
  components assembled from exported parts.
- [Forms](?path=/docs/introduction-forms--docs): fields, validation libraries, and translated
  copy.

In the sidebar, components are grouped by family. Each one opens on a **Docs** page with a live
example, its controls, the written guide, and every story.

## Principles

- Prefer semantic HTML over abstractions, and forward native props and refs.
- Target WCAG 2.2 AA; the packaged themes are tested for contrast.
- Keep options closed and typed, with `className`, `style`, and CSS variables as escape hatches.
- Use tokens for every visual decision, so a theme or one variable changes the whole system.
- Keep third-party primitives an internal detail of the components that need them.
